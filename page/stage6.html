Stage 6

Where this is going: fix the checks first, then let agents run

40–45 min

If the target and its checks are fixed before the work starts, an agent can work for a long time and you can still trust what it brings back, because it is checked against something it did not write.

On 20 November 2026 Levent Alpöge released a proof of the Riemann Hypothesis as a Lean library of about 17 million lines, written with an AI model. The next day the Lean FRO and the Mathlib Initiative certified it. Nobody read 17 million lines. Trust came from three things that did not depend on the proof itself:

Lean / Riemann HypothesisOur analysis
The statement was fixed in advance: Challenge.lean states the theorem and imports only MathlibThe plan and its checks were written before the code: the estimand, the units, and a known answer the pipeline must recover
A tool checks that the delivered proof proves exactly that statement (comparator)Every step and every claim is mapped to code and results (the plan check and the claim-by-claim decisions)
Independent kernels re-check the proofAn independent reviewer, ideally a different model, recomputes from the source data
Experts vetted the statement, not every lineThe researcher signs off the claims and the estimand, not every line of R

“Crucially, the community has added a file that isolates the statement of the Riemann Hypothesis and imports only Mathlib.”

Lean FRO and Mathlib Initiative, statement of 21 Nov 2026

What this looks like in a project

By the end of Stage 5 the project carries its own checks: a known-answer simulation, a hand-worked example whose answer is a number in the test, the heterogeneity statistics saved to a file, and a README that says how to rerun all of it. The next agent to open the folder starts from those checks, not from scratch.

Write the checks before the code. Milestones that can be checked are what let an agent work longer on its own, and what let you trust what it brings back.
