Further reading

We did not invent these practices. We collected them from the people who build these tools and from those who use them carefully, and turned them into the steps above. The quotes below are copied from the sources. Pick whatever fits your own work.

Specify first, then review against the specification

Best practices for Claude Code · Anthropic documentation
“A reviewer that’s asked to find problems will always find something.”

Covers reviewing against a written spec in a fresh session that never saw the build, and asking for evidence (the command and its output) rather than “all tests pass”.

Spec-driven development · GitHub Spec Kit
“But raw AI generation without structure produces chaos.”

The software version of a pre-registered analysis plan: specification, then plan, then tasks, then code.

Adversarial review prompt · OpenAI, codex-plugin-cc
“Your job is to break confidence in the change, not to validate it.”

A ready-made specified review: each finding tied to a file and line, ending in a ship/no-ship decision. The plugin runs Codex from inside Claude Code, so it doubles as a cross-model reviewer.

code-review skill · Matt Pocock, mattpocock/skills
“Start every sub-agent with a fresh context window.”

Keeps two questions apart: does the code meet our standards, and does it do what the plan asked?

Are LLMs reliable code reviewers? · Jin & Chen, arXiv 2603.00539 (preprint, 2026)
“…more detailed prompt design, particularly with those requiring explanations and proposed corrections, leads to higher misjudgment rates…”

A longer prompt is not the same as a specified one. What helps is something the reviewer can run and check, not more instructions to argue with.

The agentic garden of forking paths · Miao, Pritchard & Zou, arXiv 2607.01507 (preprint, 2026)
“86% passed independent AI review and 78% passed majority human expert review.”

AI analyses that reached opposite conclusions mostly passed review anyway. Passing a review does not show that the analysis is right.

Known answers and step-by-step checks

tdd skill · Matt Pocock, mattpocock/skills
“Expected values must come from an independent source of truth: a known-good literal, a worked example, the spec.”

This is the lesson of Stage 2 in one line: a test built on the same assumption as the code passes by construction.

Demystifying evals for AI agents · Anthropic, 2026
“For each task, it’s useful to create a reference solution: a known working output that passes all graders.”

The logic of a positive control: first show that the check recognises a known right answer.

Your job is to deliver code you have proven to work · Simon Willison, 2025
“That test should fail if you revert the implementation.”

A short, quotable standard for every fix: the change and the test that proves it are delivered together.

Augmented coding: beyond the vibes · Kent Beck, 2025
“Any indication that the genie was cheating, for example by disabling or deleting tests.”

Warning signs to watch for when an agent works through a test-driven loop.

Codex best practices · OpenAI documentation
“Ask it to create tests when needed, run the relevant checks, confirm the result, and review the work before you accept it.”

A second vendor giving the same advice. Its prompt template ends with a “Done when” line, a simple way to pre-specify the check.

Long runs against fixed milestones

Let Claude run without you · Anthropic documentation
“Before a run goes unattended, make sure it knows what done looks like, can check its own work, and can only touch what it should.”

Five pre-flight questions: what done looks like, how it checks itself, what it may touch, when it stops, and who signs off.

Effective harnesses for long-running agents · Anthropic, 2025
“These features were all initially marked as ‘failing’ so that later coding agents would have a clear outline of what full functionality looked like.”

Milestones written down as checks before the work starts, with a commit and a progress note at the end of every session.

Lean verification of the Riemann Hypothesis · Lean FRO and Mathlib Initiative, 21 Nov 2026
“Crucially, the community has added a file that isolates the statement of the Riemann Hypothesis and imports only Mathlib.”

Shows that the target was fixed independently of the work that claims to meet it. See also the challenge file and the author’s note.

“…and the proof is checked in Lean” · Xena project blog, 2026
“…there is an important signal that can be extracted from Lean code, but if this code is AI-generated then you need to do some tests first.”

Four questions to ask of any AI-checked result: is it the right statement, does it build, does it prove that statement, and has an independent checker confirmed it?

MR methods used in the case

Harmonise data · TwoSampleMR documentation
“…the effect of a SNP on the exposure and the effect of that SNP on the outcome must each correspond to the same allele.”

Worked examples of strand flips and palindromic SNPs. This is the step our planted error breaks.

Two-sample Mendelian randomization: avoiding the downsides of a powerful, widely applicable but potentially fallible technique · Hartwig, Davies, Hemani & Davey Smith, Int J Epidemiol 2016
“…GWAS results rarely have harmonized effect (or coded) alleles.”

Table 1 is a step-by-step harmonisation checklist.

The MR-Base platform supports systematic causal inference across the human phenome · Hemani et al., eLife 2018
Guidelines for performing Mendelian randomization investigations (2023 update) · Burgess et al., Wellcome Open Res

Can serve as the plan that a reviewer checks the analysis against.

STROBE-MR: explanation and elaboration · Skrivankova et al., BMJ 2021

A 20-item reporting checklist, ready to use for the close-out consistency check.
