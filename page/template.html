Validating an analysis written by an AI agent

An AI agent will always give you an answer. Whether it is the right answer depends on how you check it.

Xiaoyang Dai & Gibran Hemani · IEU AI-for-coding workshop · All data simulated · Every reply on this page is a recorded run.

Five things to take home

  1. An agent always returns an answer.A fluent, cautious, internally consistent report is not evidence that the numbers are right. In this case, every result that “made sense” was wrong.
  2. Ask for evidence, then read it.A simple error is found whatever you ask; a deep one only occasionally, however well you ask. A specified review lays out its working (plan-to-code checks, simulations, a decision on each claim), and that working is where you find what it missed.
  3. A known answer must be independent.A test built on the same assumption as the code passes by construction. Use a hand-worked example, a published value, or a colleague’s own calculation.
  4. Validate every step, and lock the check in.Fix, re-test, commit, so the next session, human or agent, inherits the check. At milestones, bring in a new reviewer with new questions, ideally a second model. Before release, close out: rerun, reconcile, read for contradictions.
  5. Write the checks before the code.Milestones that can be checked are what let agents work for longer on their own, and what let you trust what they bring back.
